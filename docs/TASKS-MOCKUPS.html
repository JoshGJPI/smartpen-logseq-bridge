Tasks from handwritten notes

Feasibility review and mockups, 2026-10-22. Two parts: (1) turn MyScript's task boxes into TODO / DONE that LogSeq understands, (2) a task list in the app where ticking a box writes DONE back to the page's transcript.

Verdict

Part 1 · boxes → TODO
Small, low risk

The data model already has checked and the LogSeq copy already writes TODO/DONE from it. New transcriptions just never set it. About a day including tests and a one-off conversion of old pages.

Part 2 · task system
Feasible, medium

A task index fits in the existing metadata scan (no stroke loading), and a tick is a one-line PageDoc write through the existing save path. About 3 to 4 days for the list, reader ticking and tests.

Sync with LogSeq
One-way only

Pasted tasks become separate copies. Ticking in one place won't tick the other. Two-way sync into the shared OG graph is not recommended (see LogSeq).

Part 1: task boxes → TODO / DONE small

One pure function, parseTaskMarker(text) in a new src/lib/task-markers.js, run on each new MyScript line inside mergeTranscript(). It strips the leading marker and sets the state:

Line starts withStored asCopies to LogSeq as
☐, [ ], TODOchecked: false- TODO text
☑, ☒, [x], DONEchecked: true- DONE text
☐ waiting on … / WAITINGchecked: false + marker: "WAITING" (new optional field)- WAITING on …
anything else (incl. bare ✓, •)checked: null- text

The duplicate check (isDuplicate()) compares marker-stripped text on both sides, so re-transcribing a page that still has ☐ in an old line doesn't add a second copy. marker is an additive field, so PAGE_DOC_VERSION stays "2.0", and older code reads a WAITING line as an ordinary TODO.

Part 2: a Tasks view interactive

A new Library view (libraryView: { kind: 'tasks' }, opened from a Tasks card on the Library home and from a badge in the header). Every row is one transcript line with a TODO / DONE / WAITING state. Ticking the box writes the change to that page's PageDoc straight away, like a tag change: optimistic, with an Undo and a per-page rollback if the write fails. Click the page link to open the page in the reader with the line highlighted (the reader already supports focusLineId).

Ticking in the reader

The same write is available wherever a transcript is shown read-only: the TODO / DONE marker in TranscriptLines becomes a button. Edit mode keeps its current behaviour; while a page has an unsaved transcript draft, ticking on that page is disabled with a tooltip, so a tick can never be overwritten by a draft save.

How this lines up with LogSeq

  • Paste carries state. After Part 1, Copy all / Copy branch give - TODO, - DONE and - WAITING, the only three markers you use (no DOING/NOW/LATER anywhere in the UI).
  • Optional on copy: a "Copy as my tasks" variant that adds [[Josh Gannon - TODO]] to each TODO's first line and the page's project tag as [[P2026-141]]. The project number comes only from a tag you put on the page, never guessed from the text.
  • No live sync. Once pasted, the LogSeq block and the PageDoc line are separate copies. Two-way sync would mean writing into the shared, git-autosynced OG graph from this app, which your rules route only through the logseq MCP's artifact protocol. Not worth it for this.
  • Better bridge, later: the planned read-only MCP server (docs/MCP-SERVER-SPEC.md) could add a list_tasks tool, so Claude can pull open pen tasks into a daily note through the artifact protocol, with you confirming each one.

Risks and open questions

  • Stale copies. A tick writes a PageDoc outside the Library reader's own save path, so it must refresh the reader cache and scan record (the refreshAfterSave rule). If the page is open in the Editor, its later save starts from disk and keeps existing lines untouched, so the tick survives.
  • Draft conflict. An open transcript edit on the same page would overwrite a tick on save. Handled by disabling ticks on dirty pages.
  • Re-transcribing a page appends only new lines and keeps checked on existing ones, so a DONE is not reset. Re-transcribing after deleting the transcript starts over from what the ink says, which is correct (ink still shows an empty box).
  • Paper vs app. Ticking in the app doesn't change the ink. If you later tick the box on paper and re-transcribe, the line is already DONE; no conflict.
  • Untranscribed pages have no tasks. The list is only as complete as transcription (free tier 2,000 requests/month).
  • Open question: should "waiting on …" be detected from text, or only set by hand from the row menu? Only 2 lines today.
  • Open question: should Part 1 also spot assignees ("Sam will…", "Pat will…")? Feasible as a suggestion like tag suggestions, but out of scope here.
