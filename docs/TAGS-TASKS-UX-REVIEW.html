Tags & Tasks UX Review

How page tags and transcript tasks are viewed, assigned and updated in each part of the app: Library, reader, Timeline, Editor, Tasks and search. It lists the errors found in each flow and has mockups of the recommended fixes. This review read the code. It did not run the app, and nothing in the repo was changed.

Summary

11bugs (5 can lose task state or a tag)
14UX friction
11gaps and dead ends
1 of 13places can edit both tags and tasks (the reader)

The two main places to work on tags and tasks already work well: the Library reader (tag strip, ticking boxes, the ⋯ state menu, Undo) and the Tasks view. Optimistic writes, rollback and the single task write path all hold up. The problems are at the edges:

  • Editing a transcript can wipe a task's state. Merging or splitting lines in the Edit Transcription dialog drops checked/marker. The Editor's Pages-tab save bypasses the refresh, so Tasks shows lines that no longer exist and it can overwrite a tick made in the meantime.
  • You can't make or unmake a task without ink. In the Library, typing TODO stores literal text. Nowhere can a task be turned back into a plain line.
  • Tags and tasks are invisible in half the app. The Timeline, Transcripts search, Editor Pages cards and the canvas show neither. Chips in Tasks and TagPages look clickable but go nowhere.
  • Small keyboard traps. Enter in a tag field can add a different, longer tag. Escape in the bulk-remove menu drops your selection. Holding Backspace strips every tag with no undo.

The recommended direction is one tag control and one task-line menu, used everywhere (PageTagsInline and TaskMenu), with read-only chips and an open-task count anywhere a page appears as a card.

Each row is a place in the app. Under Tags, "edit" means add and remove on that page. Under Tasks, "state" means tick, WAITING and CANCELLED, and "make" means turning a plain line into a task or back.

Fix first: bugs that lose state

I checked T1, T3, T4 and G1 against the source myself. The others come from the two code audits and are marked "suspected" where they couldn't be confirmed by reading alone.

Mockups of the recommended fixes

These use the app's light reading surface. Red outlines mark what's new. The ink and project numbers are made up.

1 · One line menu for tasks, in the reader and both editors

Make the reader's ⋯ menu the one place to set a line's state, adding Make task and Not a task. Edit mode and the Edit Transcription dialog keep the state glyph next to each line, so a task can't be deleted or merged away by accident. ←/→ stay in the menu, and Escape closes it without clearing the line highlight.

One read-and-edit row under any card that stands for a page: its tags, a "+ tag" button, and an open-task count that opens the page at its first open task. Same component everywhere (PageTagsInline in a compact mode).

Open question for you: should Not a task exist at all, or would you rather CANCELLED be the only way to retire a task? The first one changes checked back to null, which the task-state rules don't currently allow.
