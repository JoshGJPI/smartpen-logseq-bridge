UI/UX review after v3.10–v3.13

This review covers the app as it stands after Back / Forward, task chips, tag-page tasks, the Tag-home groups and the Editor's move away from Dates. I drove the built app over CDP at a 1586×937 window, using a scratch copy of the data folder, and walked the Timeline, the Library home, a notebook grid, a tag page, Tasks, the reader, the Editor and Settings. No code is changed. Each item has an ID, so you can approve, reject or change items by ID.

Findings and proposals

IDKindWhat I sawProposalSize
U1Breaks In the Editor, the header gains Save, Delete, Undo, Clear and Transcribe, which brings it to 14 buttons. At a 1586 px window the page scrolls sideways (content is 1637 px wide), the Settings gear goes off-screen and search shrinks to “Search notes,”. The window's minimum width is 1200, so this happens at sizes the app allows. Move the Editor's actions into the Editor pane's own title row, beside “Stroke Preview”. The global header then shows the same items in every view. M1M
U2Dead click On a tag page, Tasks or a notebook grid, clicking the active Library tab does nothing (navigateTo returns 'same'). The only way home is the breadcrumb or Back. Clicking the active Library tab goes to the Library home, the way a browser's home button does. The history records it as a normal entry. S
U3Duplicate The Timeline has two date controls for one range. The left Dates tab has From / To, Latest day / 1 / 7 / 30 days, an explanation box and a day list. The feed head has a date dropdown, ‹ ›, Today, a histogram and Load range. “Latest day” and “Today” are separate buttons that look alike. Make the feed head the only range control: the date dropdown opens a popover with From / To and the presets, and “Latest day” joins Today. The left tab becomes just the day list (jump to a day), with no explanation box. M2M
U4Duplicate Library and Timeline both carry a Transcripts tab. Its Review half is empty outside the Editor (“No new transcripts to review”), and its Search half repeats the header's global search, which uses the same matching (global-search.js reuses transcript-search.js). Show Transcripts in the Editor only. Outside the Editor, “search saved transcripts” is the header search. Needs check: whether you use anything in Transcripts → Search that global search lacks (for example copying from results).S
U5Mismatch The Library's left panel always shows Contents, a notebook tree that repeats the home's notebook cards. On Tasks and on a tag page it has nothing to do with what's open. Make the left panel follow the Library view. On Tasks it lists projects with open counts and jumps to a group. On a tag page it lists all tags, so you can hop between projects. In a notebook or the reader it stays as Contents. M3M
U6Crowded The JPI Dotted grid's FILTER box holds 53 tag chips across 5 rows, which is about a third of the pane before the first page. Show one row: the 6–8 tags used most recently in this notebook, then “+45 more ▾”, which opens a type-to-filter list. Selected tags stay pinned in the row. The same component serves every grid. M4M
U7Redundant On the 2237-011 tag page, “2237-011 8” is the first filter chip (it matches every page) and every tile repeats the 2237-011 pill. The real co-tags get pushed to “+1 / +3”. On a tag's page, leave the tag itself out of the filter and off the tiles, so the tiles show the other tags. M5 S
U8Crowded The tag page's Tasks panel holds 5 state chips in a narrow column, and they wrap. Waiting 0 and Cancelled 0 take as much room as the others. The All chip is a toggle that resets to the default when everything is on, which is hard to predict. Use one set of chips everywhere: the four state toggles, with zero-count states dimmed, and a small “Reset” link that appears only when the choice isn't Open + Waiting. Drop All. On the tag page, show the counts in a compact form. M5S
U9Label One sort has three names: “Recently written” (Library home), “Recent” (notebook grid) and “Last edited” (tag page). Page order is called “Page ↑ / Page ↓” in one place and “Notebook” in another. Use Recent and Page order everywhere, keeping ↑ ↓ only where both directions exist. Keep “Last edited” out, because it suggests a file-write time, which is the lastUpdated trap.S
U10Label When P179 is opened from a Recent-sorted grid, the reader shows the spread “P179–P192 of 131”. The page ids look like a page range (P180–191 don't exist), and “of 131” is a count, not a page number. The breadcrumb reads “P179 · P192”, with “113 / 131” as a separate muted position. Also consider making Single the default when a page is opened from a grid sorted by Recent, since the spread partner is not what you just looked at. M6S
U11Crowded Each reader page has its own row for the ↺ “Portrait” ▾ ↻ rotation control, and the row is always visible. Rotation is set about once per page, ever. Show rotation as a small ⟳ button on the page corner when you hover, with the choices in its menu. This gives the page one row back. M6S
U12Empty state The empty Editor shows two rows of disabled tools, “Page Resets ▾”, a bottom bar with “Filter: 0/0, No pages”, and the load hint in the left panel, not on the canvas. When the canvas is empty, hide the tool rows and put the hint on the canvas as buttons: Open Timeline, Pick pages, Connect pen. Rename “Page Resets ▾” to “Layout ▾” (it resets page positions and scaling). Rename “Stroke Preview” to “Editor”. M7S
U13Order Settings opens on MyScript keys, which are set once. Pen and Notebooks, which you change more often, are further down. Convert task boxes…, a one-off migration, sits among the Data Folder actions. The emoji icons don't match the app's line icons. Reorder to Pen, Notebooks, Data folder, Publish to LogSeq, MyScript, Maintenance (Convert task boxes, Activity Log). Make each section collapsible, and use line icons. M8S
U14Placement The Library home's top row mixes view controls (Notebook | Tag, the sorts) with maintenance (Rescan). Manage tags shows while grouped by Notebook, where it has nothing to act on. Move Rescan into a ⋯ menu at the end of the row (and keep it in Settings → Data folder). Show Manage tags only in Tag grouping. S
Working well, keep as is: Back / Forward with named tooltips, the sticky Tasks head, project headings that open the tag page, tile date ranges, the Timeline's Today, and the header Tasks count.

Approval list

Reply with IDs, for example “U1, U2, U6, U7 yes; U3 later; no U13”. Suggested order, with the cheapest and most visible first:

  1. Fix first: U1 (Editor header overflow) and U2 (Library tab goes home).
  2. Small, clear wins: U7, U8, U9, U10, U12, U14.
  3. Layout changes worth a mockup round in the app: U6 (tag filter), U11 (rotation on hover), U13 (Settings).
  4. Bigger restructures: U3 (one Timeline range control), and U4 with U5 (a left panel that follows the view). These touch lib/left-panel.js CONTEXT_TABS and should go in one change.

None of these change storage, PageDoc format, task writes or tags in _tags.json. They are display and layout only. U1 moves buttons but keeps their handlers (ActionBar, which is over the ~300-line guideline and would be split while it is touched).
